What you're watching

One engine. The CLI runs it natively;
your browser runs it in WebAssembly.

There is no simulation layer and no pre-rendered data — the tab you're in is doing the same work a feed handler does.

01 / RAW BYTES

The wire format, unmodified

Your browser downloads ~1.6 MB of gzipped ITCH 5.0 — the binary format Nasdaq actually disseminates. 157,824 length-prefixed messages: adds, executions, cancels, deletes, replaces.

02 / ONE ENGINE

The same Rust the CLI runs

The bytes stream through limitbook-core, a #![no_std] crate that parses zero-copy straight off the byte slice — the exact crate behind the native CLI, compiled unchanged to wasm32-unknown-unknown.

03 / BOOK IN YOUR TAB

Reconstructed, then proven

Every price level above is computed in your tab, with a deep consistency check every 1,000 messages. When the replay completes, the final book is compared tick-for-tick against limitbook replay's output for the same slice.

Measured, not estimated

The numbers behind the demo.

268.7M
messages · full trading day

The complete 2019-12-30 TotalView sample day — 268,744,780 messages — replayed through parser and book with zero invariant violations and zero parse errors.

31.9M msg/s
zero-copy parse · single core

≈1 GB/s of raw feed decoded on one Xeon core, verified by a per-run timestamp checksum. Full book reconstruction included: 1.38M msg/s.

wasm ≡ CLI
parity · enforced by CI

The browser build must reproduce the CLI's final book state tick-for-tick on both committed fixtures — asserted in the test suite on every push, and again live at the end of the replay above.
